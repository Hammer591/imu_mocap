# IMU Mocap 项目开发记录

## 2026-07-17

- 确认 `jetson_parse_mocap.py` 功能：解析 STM32 USB CDC 发送的四路 IMU 数据包（172 字节/包，CRC32 校验）
- 验证协议结构：SOF + 24 字节头部 + 144 字节浮点数据（4 IMU × 9 float）+ 4 字节 CRC
- 首次在 PC 上运行，遇到 `/dev/ttyACM0` 权限问题
- 永久解决：添加 udev 规则 `99-ttyacm.rules`

## 2026-07-18

- 成功接收 STM32 数据，确认解析器工作正常（120 包全部 CRC 通过，0 错误）
- 发现数据问题：`seq=0` 始终不变、`valid_mask=0b0000`、`flags=0x00`、`stm32_time=0`
- IMU 数据有数值变化（非全零），判断 STM32 固件可能未正确初始化 IMU 或 IMU 未连接，最终确认问题为电源未正确启动
- 确定要在 PC 上搭建 ROS2 节点发布 IMU 数据
- 系统为 Ubuntu 20.04，已预装 ROS1 Noetic
- 选择安装 ROS2 Foxy（Desktop），后续迁移至jetson需要更换为 Humble 适应 RTABmap
- USTC 镜像源因 Foxy EOL 返回 404，相关安装包已被删除，换用 ROS官方安装 Foxy 环境成功
- 创建 ROS2 工作空间 `~/imu_mocap_ws/`
- 编写 ROS2 节点 `mocap_node.py`：后台线程读取串口，发布 `sensor_msgs/Imu` 和 `MagneticField` 话题
- 发现 setuptools 72.x 不兼容 console_scripts 入口点生成，改用 `scripts/` + 直接 python 启动
- 运行中遇到 `stamp` 类型错误（`rclpy.time.Time` 不能直接赋值给 header.stamp），修复为 `builtin_interfaces.msg.Time`
- 线程中 `rclpy.ok()` 在非主线程不生效导致卡死，修复为仅用 `self._running`
- 最终节点正常运行，每 1000 包打印统计信息
- 确认 STM32 数据仍为静态（seq、timestamp、IMU 值全部不变）
- 最终结论：问题不在本 PC 软件栈（原始脚本和 ROS2 节点行为一致），在 STM32 固件端
- 重新拔插完全重启硬件后恢复正常动态数据流，确认问题为不可以在运行状态下断开 imu ，否则会导致 stm32 不识别设备，此时必须完全切断电源断开 USB 后重启硬件

## 启动方式

### 原始脚本（直接查看串口数据，不依赖 ROS2）

```bash
# 带终端打印（每 20 包打印一次）
python3 ~/imu_mocap/jetson_parse_mocap.py

# 静默记录到 CSV
python3 ~/imu_mocap/jetson_parse_mocap.py --csv data.csv --print-every 0

# 自检（不连硬件）
python3 ~/imu_mocap/jetson_parse_mocap.py --self-test
```

### ROS2 节点（发布标准 IMU 话题）

```bash
# 一键启动
~/imu_mocap/run_ros2_mocap.sh

# 或手动 source 后运行
source /opt/ros/foxy/setup.bash
source ~/imu_mocap_ws/install/setup.bash
export PYTHONPATH="~/imu_mocap_ws/install/imu_mocap_node/lib/python3.8/site-packages:$PYTHONPATH"
python3 -c "from imu_mocap_node.mocap_node import main; main()"

# 查看发布的话题
ros2 topic list
ros2 topic echo /imu0
```

## ROS2 节点架构

```
话题:
  /imu0  ~ /imu3    sensor_msgs/Imu         加速度 + 角速度
  /imu0/mag ~ /imu3/mag  sensor_msgs/MagneticField  磁力计

帧 ID: imu0, imu1, imu2, imu3
```

## 已知问题

- 数据中的 `header.stamp` 当前使用 `time.monotonic_ns()`（系统启动时钟），非墙上时间
- IMU 四元数姿态未填充（orientation_covariance = -1 标记未知），需要后续 IMU 数据正常后再实现
